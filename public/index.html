    A SHORT FIELD GUIDE

    Read the permissions

    An authority address tells you who holds a role. It does not tell you whether that address is trustworthy.

    Ordinary delegate

    A token-account owner can give another address permission to transfer or burn up to a recorded allowance. Only one ordinary delegate is stored per account.

    A zero allowance means no remaining ordinary allowance, even if a delegate address is still recorded.

    Permanent delegate

    Token-2022 can assign a delegate to the mint itself. It applies across token accounts for that mint, even if their ordinary delegate fields are empty.

    Token-account owners cannot revoke this mint-level permission from their own accounts.

    Close authority

    This address can authorize closing the token account when the token program’s conditions allow it. If no separate close authority is set, the owner holds that role.

    For wrapped SOL, closing can withdraw the underlying SOL even when the token balance is nonzero.

    Frozen and unverified

    A frozen account blocks ordinary transfers and burns until it is thawed. Its recorded authorities still matter.

    “Unverified” means a read failed or an extension is outside this tool’s decoding scope. It never means “none.”

    How to use it

    1. Try an offline example first.
    2. Paste a public address and choose Mainnet or Devnet.
    3. Inspect each account’s ordinary and mint-level authority fields.
    4. Read partial observations and extension notes.
    5. Export JSON or Markdown to keep a copy.

    Amounts use integer raw units and base mint decimals. Scaled or interest-bearing display adjustments are not calculated. No account data or lookup history is saved by the app.

    Small by design

    The server binds to 127.0.0.1. Live reads use public RPC; examples stay offline. There is no wallet connection, transaction submission, database or cloud backend.
